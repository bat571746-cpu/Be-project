How the pipeline works

QAES runs every file through two independent encryption stages before it's written to disk. This page explains what each stage does and why it's designed this way — useful background if you're presenting or writing up this project.

01

Quantum stage — seed generation

A quantum circuit puts qubits into superposition with a Hadamard gate, then measures them. Quantum mechanics guarantees the outcome of each measurement is fundamentally undetermined until it happens — not merely hard to predict, like a classical pseudo-random number generator, but genuinely probabilistic. This runs on Qiskit's AerSimulator by default, so the app works offline without an IBM Quantum account.

The measured bits become a 16-byte quantum seed and a 12-byte nonce, implemented in core/qrng.py.

02

Key derivation — combining both secrets

The quantum seed alone isn't the encryption key. It's concatenated with your password and stretched through PBKDF2-HMAC-SHA256 at 390,000 iterations (the OWASP-recommended minimum) to produce the actual 256-bit AES key. This is the "double" in double encryption: an attacker needs both your password and the quantum seed to derive the key. The seed is stored in the output file's header — similar to a salt — so it isn't secret on its own, but it can't be guessed either. Implemented in core/crypto_engine.py.

03

AES stage — confidentiality and integrity

The derived key drives AES-256 in GCM mode, an authenticated cipher: it doesn't just hide your data, it also produces a 16-byte tag that proves the ciphertext wasn't altered. If even one byte changes — or the wrong password is used — decryption fails outright instead of silently returning garbage. Implemented in core/aes_cipher.py using Python's audited cryptography library.

Frequently asked

Why not hand-roll the AES math too?
Hand-rolled AES is extremely easy to get subtly wrong, and a flawed implementation provides no real security regardless of how well it's understood. The novel, "from scratch" contribution of this project is the quantum random number generation pipeline — circuit design, bit extraction, and unbiased integer sampling — not a reimplementation of a 25-year-old standard that production systems also don't reimplement themselves.
Is the randomness really quantum, or simulated?
The circuit logic (superposition + measurement) is run on Qiskit's Aer simulator, which simulates the quantum mechanics classically. The same circuit can be pointed at real IBM Quantum hardware instead — see the comments at the bottom of core/qrng.py — but that requires an account and has queue wait times, so the simulator is used by default for a responsive app.
What happens if I forget my password?
There is no recovery. The password is never stored anywhere — only used transiently to derive the key — so a forgotten password means the file cannot be decrypted by this tool or anyone else.
Does any data leave this machine?
No. The web console talks only to a Flask server running on 127.0.0.1 (your own machine). No file or password is ever sent over the network.
